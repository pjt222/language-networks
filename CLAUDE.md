# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

Frontend (Vite + vanilla JS, D3.js):

```bash
npm run dev              # Vite dev server (with proxy for gutenberg + dwds)
npm run build            # Production build → dist/
npm run preview          # Preview built dist/
npm test                 # Vitest one-shot
npm run test:watch       # Vitest watch mode
npx vitest run tests/scales.test.js   # single test file
npx vitest run -t "node size"          # tests matching name
npm run download-corpora # Refresh public/data/dwds/*.json from DWDS
```

Backend (Rust, Axum):

```bash
cd backend && cargo run         # Serves API + ../dist on :3000
cd backend && cargo test        # All tests (4 unit processor + 4 unit graph_builder + 3 integration)
cd backend && cargo test --test corpus_test   # integration tests only
cd backend && cargo test processor::tests::test_name   # single test
```

Note: `backend/target/` is gitignored; the backend serves built `dist/`, so run `npm run build` before exercising production-mode serving from Rust.

## Architecture

### Two-pipeline parity
The same corpus → trie → graph pipeline exists in **JS (canonical, runs in browser)** and **Rust (mirror, scaffold)**. Keep them behaviorally aligned:

| Stage         | JS                                        | Rust                                      |
|---------------|-------------------------------------------|-------------------------------------------|
| Tokenize      | `src/corpus/processor.js`                 | `backend/src/corpus/processor.rs`         |
| Trie + edges  | `src/corpus/graphBuilder.js` (`buildGraph`)| `backend/src/corpus/graph_builder.rs`     |
| HTTP API      | —                                         | `backend/src/api/handlers.rs` (POST /api/process-corpus, GET /api/samples/:name) |

Tokenizer rules: NFC + lowercase, `\p{L}+` regex, drop length ≤1 or >50.

Graph node id `ROOT` is the synthetic origin of the trie. `position` field = char index from ROOT (1-based). When `includeTerminal: true`, each word ends at a virtual `END` child node.

### Frontend rendering pipeline
Entry: `src/main.js` → `LayoutManager` (`src/graph/layoutManager.js`) owns the SVG, scales, simulation, and dispatches to one of eight layouts:

- **force** — `d3.forceSimulation`, drag enabled, link path style `straight`
- **radial** — `d3.forceRadial` (force-based, NOT static fx/fy), rings drawn behind, link style `radial`
- **circularTreeDepth** — `d3.cluster` polar projection, all leaves pinned to outer ring (canonical phylogenetic dendrogram). Polar collision pass (strong `forceRadial` + tangential `forceCollide`) locks `fx/fy`. Link style `radial`.
- **circularTreePosition** — `d3.cluster` for angular allocation, `radiusScale(node.position)` for radius. Rings = trie depth, siblings adjacent. Same polar collision lock. Link style `radial`.
- **hierarchical** (Tree) / **cluster** — static positions via `d3.tree`/`d3.cluster`, links resolved through `nodeById` map, styles `straight`/`step`
- **circular** — concentric rings by position, link style `arc`
- **hive** — categorical axes, link style `hive`

**Polar collision pattern** (used by `circularTreeDepth`, `circularTreePosition`): instead of generic `resolveCollisions` which uses x/y forces, these layouts use `d3.forceRadial` with strength 3.0 anchoring each node to its target ring, plus `forceCollide` strength 1.0. Effect: nodes can only drift tangentially along the ring, so concentric structure is preserved even at high node density. 150 sync ticks then `fx/fy` lock.

Adding a layout: implement `create<Name>Layout()` returning positioned nodes (or a simulation), wire a `_render<Name>()` branch in `LayoutManager.render()`, add an `updateLinkPaths` style in `src/graph/renderer.js`, and add a radio option in `index.html` (controls use generic `input[name="layout"]` so no JS UI change needed).

`_cleanupDecorations()` runs before each render to strip layout-specific overlays (rings, markers, axes). Static layouts must build a `nodeById` map and re-resolve link `source`/`target` to node objects (force layouts do this via `forceLink`).

`resolveCollisions` (`src/graph/resolveCollisions.js`) runs collision relaxation post-positioning for static layouts. Node radius lives on `node._radius` (set by `createNodeSizeScale`, range `[10, 30]`); when changing the size range, also update `tests/scales.test.js`.

### Vite dev proxy
`vite.config.js` proxies `/gutenberg` → gutenberg.org, `/dwds-static` and `/dwds-api` → dwds.de to dodge CORS during dev. `src/utils/fetcher.js` consumes these.

### Static corpus data
`public/data/dwds/*.json` is regenerated by `scripts/download-corpora.js` (Goethe A1/A2/B1 lemma lists + DWDS headwords). Don't hand-edit.

## Testing notes

- Frontend: Vitest, ~45 tests under `tests/`. `scales.test.js` asserts the node size range — sync with `createNodeSizeScale` changes.
- Backend: stdlib `cargo test`. Integration tests in `backend/tests/corpus_test.rs` exercise the Axum router end-to-end.
- Two pipelines = parity tests when changing tokenizer/trie semantics; update both sides + their tests.
